== COMPILAR VARIANTES DE OPTIMIZACION POR COMPILADOR (PowerShell) ==
Genera bin/matmul_<etiqueta>.exe, un ejecutable por combinacion de flags
(ver https://gcc.gnu.org/onlinedocs/gcc/Optimize-Options.html):
  O0        -O0                                  sin optimizacion
  O1        -O1                                  optimizaciones basicas
  O2        -O2                                  nivel estandar (linea base del proyecto)
  O3        -O3                                  + vectorizacion agresiva, inlining
  Ofast     -Ofast                               -O3 + relaja reglas de punto flotante
  Os        -Os                                  optimiza tamano del binario
  O3native  -O3 -march=native                    usa todas las instrucciones SIMD de esta CPU (AVX2...)
  O3unroll  -O3 -funroll-loops                   desenrolla bucles
  Ofastfull -Ofast -march=native -funroll-loops  todo junto

$flags = [ordered]@{ O0='-O0'; O1='-O1'; O2='-O2'; O3='-O3'; Ofast='-Ofast'; Os='-Os'; O3native='-O3 -march=native'; O3unroll='-O3 -funroll-loops'; Ofastfull='-Ofast -march=native -funroll-loops' }; foreach ($k in $flags.Keys) { gcc $flags[$k].Split(' ') -Wall -Wextra -Wpedantic -std=c11 -o "bin/matmul_$k" src/matmul.c -lm }

== 4) OPTIMIZACION (compilador + codigo): 10 turnos x 9 flags x 3 algoritmos x 8 tamanos ==
Requiere haber compilado las variantes. Algoritmos (opcion -a de matmul):
  clasico     i-j-k, fila x columna (definicion de libro, B recorrida por columnas)
  ikj         i-k-j, el codigo original usado como linea base
  traspuesta  se traspone B y se multiplica fila x fila
Las dos primeras columnas de cada linea son la etiqueta de flags y el algoritmo.
Tarda alrededor de 1 hora (casi todo es -O0 y el algoritmo clasico con N grande).

"Flags;Algoritmo;Orden;Tiempo(s);Rendimiento(GOP/s)" | Out-File resultados_optimizacion.csv -Encoding utf8; 1..10 | ForEach-Object { foreach ($f in 'O0','O1','O2','O3','Ofast','Os','O3native','O3unroll','Ofastfull') { foreach ($a in 'clasico','ikj','traspuesta') { foreach ($n in 250,500,750,1000,1250,1500,1750,2000) { "$f;$a;" + (& ".\bin\matmul_$f.exe" -n $n -l 100 -a $a -c) | Out-File resultados_optimizacion.csv -Encoding utf8 -Append } } } }

== OPENMP ==

Sentinela: #pragma omp (directiva ignorada si se compila sin -fopenmp)
Cabecera:  #include <omp.h>
Directiva usada (ganadora del analisis): #pragma omp parallel for schedule(static)

== COMPILAR mmOPENMP (PowerShell) ==
gcc -O2 -fopenmp -Wall -Wextra -std=c11 -o bin/mmOPENMP src/mmOPENMP.c -lm

== EJECUTAR mmOPENMP ==

  Con opcion -t (numero de hilos desde la linea de comandos):
.\bin\mmOPENMP.exe -n 1000 -l 100 -t 4

  Con variable de entorno OMP_NUM_THREADS:
$env:OMP_NUM_THREADS = 8; .\bin\mmOPENMP.exe -n 1000 -l 100

  Prueba rapida con impresion (matrices pequenas):
.\bin\mmOPENMP.exe -n 5 -l 9 -s 42 -p

  Benchmark rapido (1,2,4,8,16 hilos en N=1000):
foreach ($t in 1,2,4,8,16) { .\bin\mmOPENMP.exe -n 1000 -l 100 -t $t -c }

== VARIABLES DE ENTORNO OPENMP (no requieren recompilar) ==
  $env:OMP_NUM_THREADS = 8                  # cuantos hilos usar
  $env:OMP_SCHEDULE = "static"              # como repartir iteraciones (static, dynamic, guided, auto)
  $env:OMP_SCHEDULE = "dynamic,64"          # dynamic con bloques de 64 filas
  $env:OMP_PROC_BIND = "close"              # pegar hilos a nucleos cercanos (NOTA: MinGW no lo soporta en Windows, da warning inofensivo)
  $env:OMP_PLACES = "cores"                 # hilos en nucleos fisicos (NOTA: idem, requiere MSVC o Linux)
  $env:OMP_WAIT_POLICY = "active"           # hilos ociosos dan vueltas (mas rapido en benchmarks)
  $env:OMP_DISPLAY_ENV = "true"             # mostrar TODA la config OMP al arrancar
  $env:OMP_DYNAMIC = "false"                # no dejar que el runtime reduzca hilos

  Ejemplo completo:
  $env:OMP_NUM_THREADS=8; $env:OMP_SCHEDULE="static"; $env:OMP_PROC_BIND="close"; $env:OMP_PLACES="cores"; $env:OMP_WAIT_POLICY="active"; .\bin\mmOPENMP.exe -n 1000 -l 100

  Para limpiar variables despues de probar:
  Remove-Item Env:OMP_SCHEDULE -ErrorAction SilentlyContinue
  Remove-Item Env:OMP_DISPLAY_ENV -ErrorAction SilentlyContinue


== NOTAS SOBRE OpenMP ==
  - OpenMP ya viene incluido con gcc (MinGW). No hace falta instalar nada extra.
  - La flag -fopenmp activa tanto la compilacion como el enlace de la libreria.
  - Sin -fopenmp, los #pragma omp se ignoran y el programa corre secuencial.
  - OMP_NUM_THREADS controla hilos sin recompilar. La opcion -t hace lo mismo.
  - OMP_SCHEDULE controla la politica de reparto sin recompilar (static, dynamic, guided).
  - omp_set_dynamic(0) asegura que se usen exactamente los hilos pedidos.
  - mmOPENMP.c usa schedule(runtime) para poder controlar el reparto con OMP_SCHEDULE.
  - Por defecto usa "static" (si OMP_SCHEDULE no esta fijada).
  - Analisis completo de las 6 directivas y variables: ver analisis_openmp.md
